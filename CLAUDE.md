# Инструкции для Claude Code

Проект: RAG-ассистент по законодательству Республики Казахстан. Учебный портфолио-проект Java-разработчика, переходящего в AI-инженерию.

**Главный документ — `docs/PLAN.md`**: этапы, задачи, критерии готовности и журнал прогресса. Прочитай его в начале каждой сессии.

## Как работать

1. В начале сессии: прочитай `docs/PLAN.md`, найди текущий этап (первый не ✅), коротко скажи пользователю, что будешь делать.
2. Работай **по одному этапу**. Сначала MVP (этапы 1–6); уровень 2 (слои 2.1–2.4) — только после готового MVP и по явной просьбе пользователя. Не начинай следующий этап, пока критерии готовности текущего не выполнены или пользователь явно не разрешил.
3. **Не расширяй MVP.** Идеи сверх плана записывай в «Уровень 2» или в раздел «Что дальше» README, а не делай сразу.
4. Если нужный код уже есть в doc-search или учебных проектах 2.3 (RRF, reranker, doc-eval, LLMGateway, воркер) — перенеси и адаптируй, а не пиши заново. Путь к проекту уточни у пользователя.
5. Внутри этапа иди по задачам по порядку; после каждой законченной задачи отмечай `- [x]` в `docs/PLAN.md`.
6. Каждая задача заканчивается проверкой: тесты, `uv run ruff check .`, ручной прогон. Не отмечай задачу выполненной, если проверка не проходила.
7. В конце этапа (или сессии):
   - статус этапа в таблице «Текущий статус» и узел на схеме «Дорожная карта» (✅ / 🟡);
   - запись в «Журнал прогресса» (сверху): что сделано, замеренные цифры, проблемы и как решены, что дальше;
   - новое архитектурное решение → строка в `docs/decisions.md`;
   - те же статус и запись журнала — в документ claude.ai «Задание для Claude Code: RAG-ассистент» (https://claude.ai/artifact/Wbc8dWckC4kf3ScPmauDDm), если доступен коннектор Claude Docs; источник правды — `docs/PLAN.md`;
   - коммит: `Этап N: <кратко>` (push делает пользователь).
8. Если отступаешь от плана (другая библиотека, другой подход) — объясни причину пользователю и запиши в `docs/decisions.md`.
9. Если задачу нельзя выполнить без пользователя (нужен API-ключ, ручная проверка эталонных ответов, запуск Docker) — скажи прямо, отметь ⛔ с причиной и переходи к тому, что можно сделать.

## Окружение

- Windows + PowerShell. Команды давай напрямую, без `make`: `uv run pytest`, `uv run ruff check .`, `docker compose up -d --wait`.
- Зависимости только через `uv add` / `uv add --dev`; тяжёлое ML — в extra `ml`.
- Файлы — всегда `encoding="utf-8"`, пути — `pathlib`.

## Код

- Python 3.12+, async везде, где есть I/O. Типы на всех публичных функциях.
- SQLAlchemy 2.0 (async), миграции только через Alembic — никаких `create_all`.
- Настройки только через `docs_assistant.config.Settings`; секреты — `SecretStr`, никогда не в логах.
- Без LangChain и LlamaIndex: шаги RAG пишем явно.
- Промпты — в `src/docs_assistant/generation/prompts/`, не строками посреди логики.
- Тесты: юнит без сети и инфраструктуры; всё, что требует Docker, — с маркером `integration`. LLM и эмбеддинги в тестах мокаются.
- Комментарии и сообщения — на русском. Неочевидные RAG-решения (префиксы e5, RRF, почему `simple` tsvector) поясняй коротким комментарием: пользователь учится.

## Команды

```powershell
uv sync                         # зависимости
uv sync --extra ml              # + sentence-transformers (с этапа 3)
docker compose up -d --wait     # инфраструктура
uv run docs-assistant fetch     # скачать корпус из data/sources.yaml
uv run docs-assistant register  # учёт документов в БД (с этапа 3 — часть index)
uv run docs-assistant index     # индексация (с этапа 3)
uv run docs-assistant ask "вопрос"                       # с этапа 4
uv run docs-assistant eval --mode hybrid --name hybrid   # с этапа 5
uv run pytest                   # юнит-тесты
uv run pytest -m integration    # интеграционные (нужен docker compose)
uv run ruff check . ; uv run ruff format .
uv run docs-assistant api --reload
uv run alembic upgrade head     # с этапа 1
```
